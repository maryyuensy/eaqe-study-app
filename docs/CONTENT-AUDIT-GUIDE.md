# 題目來源與使用權審核指引

審核表：[`content-source-rights-audit.csv`](./content-source-rights-audit.csv)

每列對應一道題目。表格只保存題目 ID 及審核資料，不複製題幹、選項或答案。更新題庫後，執行 `npm run audit:content-rights`；工具會按穩定 ID 合併新題目並保留人工填寫的審核欄位。題目移除時，舊列仍會留在表格，供核對既有發布紀錄。

逐題記錄以下內容：

- `source_type`：原創、自擬、獲授權、官方公開資料或其他可辨識類別。
- `source_reference`：具體文件、版本、網址、頁碼或檔案位置；不要只寫「課本」。
- `transformation_notes`：記下自行構思的情境、推理及選項，或與來源相同的部分。只改字眼、次序或人物名稱不等於取得權利。
- `rights_basis`：說明權利由誰持有、何種書面許可或其他實際依據；不確定時保留「待審」，不要自行推定公開可免費商用。
- `answer_source`、`verified_date`：記錄答案根據及最近一次核實日期；法律或規則更新時重新核查。
- `reviewer`、`approved_for_publication`、`decision_notes`：留下審核者、決定及理由。只有權利依據和答案準確性均有可檢查證據時，才可改為「是」。

產生工具預設將所有題目設為「未審核」及「否（待審）」。匯入題庫、重跑工具或把題目改寫，不會自動令內容獲准發布。未核准題目不得進入收費題庫；如無法確認，先停用該題並保留紀錄。

## 重建書本衍生題目的編寫方式

- 不把原書題目當作改寫底稿；只取考試綱要所列的考核概念，另行構思情境、問題、推理步驟、干擾項及解說。
- 可以參考考試的一般形式，例如五選一、獨立題或個案題；不得複製書本或官方範例題的句式、選項組合或個案結構。
- 使用官方公開綱要界定範圍；涉及法例、日期、主管機關或現行程序時，另查相關官方原始資料，記錄網址及核實日期。
- 人物姓名、地點或數字的替換，以及調換選項次序，均不足以證明內容可商用。不要以降低文字相似度、避開偵測或混淆來源作為驗收方法。
- 新題先放在 `docs/question-drafts/`，以 `draft` 狀態驗證題目結構及答案；完成教學、事實及權利審核前，不匯入 `dist/questions.json`，不公開、不收費。
- 官方網站上可讀取的範例或教材，不應預設為可複製或可商用。只參考一般題型；必要的引用須符合適用條件並取得法律審閱。

尚未完成答案、教學質素及權利核實的草稿只存放於本機工作資料夾，不列入公開題庫或此公開登記冊。
