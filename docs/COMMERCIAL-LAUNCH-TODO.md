## 1. 交付目標與使用方式

在保留目前網站風格及練習流程的基礎上，讓公眾可以註冊帳戶、試用免費題目、付款購買限時通行證，並在手機和電腦看到同一份作答及重溫紀錄。

目標流程：

**進入網站 → 試做免費題 → 註冊並驗證電郵 → 保存進度 → 購買通行證 → 解鎖題庫 → 跨裝置練習及重溫 → 到期後保留紀錄。**

本文件用於安排實作，不授權立即開啟真實收款或替使用者接受服務商條款。2026-10-03 Voyce 授權開發者自行完善可獨立完成的部分；技術基礎按可調整的開發基準繼續推進。商業規則中的「建議」仍須在受影響功能接入／公開收費前確認，不要求所有上線政策先定案才能開始 CP1。

### 第一版暫不包含

原生 iOS／Android App、微信小程序、自動續訂、優惠碼、推薦獎勵、社群、排行榜、開放領域 AI 對話、完整離線題庫、多人同時編輯、完整內容管理後台及大幅重新設計頁面，均不在本輪範圍。

理由題驗證、完整限時模擬試及新的課本內容也不自動納入本輪。AI 範圍限於每題作答後的補充解說，以及該題脈絡下的 EAQE／SQE 考試問答，不提供一般聊天或個別真實交易法律意見。AI 接入尚須選定供應商、估算延遲與每帳戶成本、設定用量上限及核實來源流程。API 金鑰只能存於伺服器端秘密設定，不得放入瀏覽器程式碼或 Git。若新增理由驗證或模擬考試，需另估工期；不得把目前答對選項的紀錄宣稱為「已驗證理解理由」。

| `review_state` | user ID、question ID、待重溫原因、成功日期、下次重溫、狀態 | 由作答事件推導；不可由前端直接宣告完成 |
| `reading_progress` | 用戶、概念／單元 ID、明確標記完成時間 | 如保留閱讀標記才啟用；不因打開頁面自動當完成 |
| `usage_segments` | user ID、device／session ID、時間區間、有效秒數、事件 ID | 後端檢查重複、負數、異常長度及跨裝置重疊 |
| `orders` | user ID、金額、貨幣、Stripe ID、付款／退款狀態 | 僅後端可寫；外部付款 ID 唯一 |
| `access_grants` | 訂單、解鎖範圍、開始／結束時間、撤銷狀態 | 僅後端可寫；每筆有效付款最多產生一份授權 |
| `payment_events` | Stripe event ID、處理狀態、次數、錯誤摘要 | 僅後端；event ID 唯一，支援重試及追查 |
| `account_requests`／`audit_log` | 刪除／客服操作、執行人、原因、結果 | 僅必要角色可讀寫；避免存放完整題目及敏感付款資料 |

RLS 可以把列層級權限放在資料庫；具特權的 service key 可能繞過 RLS，因此後端仍要自行驗證帳戶及操作範圍。參考：[Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)。
